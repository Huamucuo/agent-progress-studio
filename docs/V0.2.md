# V0.2: MCP Apps and Work compatibility plan

> Historical development notes for 0.1.1-rc.4. These describe implementation intent or earlier observations; they do not certify current safety or host compatibility. The original baseline had five independent-review findings; the current branch implements fixes. Current review status and remaining limits are recorded below. Read [KNOWN-ISSUES.md](KNOWN-ISSUES.md) and [VERIFICATION.md](VERIFICATION.md) before using a real session.


规划日期：2026-10-09。此计划在 V0.1 的代码、Windows 启动器、26 项核心/集成测试和 7 个浏览器流程通过后编写。**V0.2 尚未实现，不属于本版交付能力。**

Keep the local browser product usable throughout. Release a host adapter only after its real host flow passes. Official capability research and citations are in [INTEGRATIONS.md](INTEGRATIONS.md).

## First increment: read-only MCP App

Reuse the state engine and UI components through the reserved `SnapshotHost` interface. Implement two bounded tools: `aps_get_snapshot` and `aps_get_evidence`. Associate a `ui://agent-progress/summary` resource using `_meta.ui.resourceUri`; serve `text/html;profile=mcp-app` and use the negotiated JSON-RPC `ui/*` bridge.

Include task/source labels, acceptance states, missing-data labels and an explicit refresh action. Fetch detailed evidence only when requested. A sandboxed component cannot silently scan local drives or assume continuous background delivery. Detect optional host features, including `window.openai`, and retain a fallback.

中文首批范围：只读任务摘要、验收清单、证据详情与明确刷新。保持与独立网页一致的状态含义，缺失信息继续显示未知；不在组件里重复实现采集逻辑。

## Reachability decision before deployment

ChatGPT's documented remote MCP flow needs a reachable server. A user's loopback service is not automatically accessible. Start with an explicitly imported, sanitized snapshot or a host-confirmed local transport. Before any cloud bridge, present the exact schema and data preview for approval.

Default shared fields should be criterion IDs/states, bounded aggregate metrics and source revision. Prompts, diffs, local paths, file contents and secrets remain local unless the user separately chooses particular evidence. Do not introduce a public tunnel, upload, credential forwarding or background sync as an implicit consequence of installing the App.

在确定可达方式之前，不承诺“安装后自动看到当前本机任务”。本地实时采集与完整 Git 浏览继续由独立网页承担。

## Work capability probe

Verify the exact Work host/version with a small test resource. Check tools, UI resources, lifecycle notifications and extension surfaces individually. Record a capability matrix with explicit unavailable states. A documented sidebar/viewer extension is a host-provided surface, not authority to rewrite the native interface.

If there is no verified task-event stream, support manual snapshot refresh/import. The V0.1 Codex adapters remain independently usable. Do not install Hooks until a concrete missing event justifies them and the exact local definition has been reviewed.

## Subsequent increment: human review

After read-only host compatibility is proven, consider `aps_record_review`. Require an explicit action, display the criterion/evidence version, check fingerprints on the server and reject stale dialogs. Respect host permission prompts. Never infer approval from model prose, tool success or opening the component.

Hooks, if necessary, must be opt-in and bounded: emit approved IDs, timestamps and status to one local spool; avoid network access, credentials, tool rewriting and blocking pre-execution decisions.

## Release gates

| Gate | Required evidence |
| --- | --- |
| MCP resource negotiation | Real host renders the resource; unsupported MIME/capabilities fall back cleanly |
| Message boundary | Malformed, cross-origin and unrelated-session messages rejected; no raw HTML insertion |
| Privacy | Reviewed sample export excludes unapproved prompts, paths, diffs and credentials |
| State parity | Same snapshot produces identical acceptance and unknown states in both views |
| Recovery | Reload/reconnect/expired resources preserve source labels and invalidate stale approvals |
| Human interaction | Chinese/English, keyboard access and persistent confirmation checked in the real host |
| Work support claim | Recorded host/version and actual supported flow, beyond a generic browser test |
| V0.1 regression | All existing local tests still pass without an online account |

Release order: read-only MCP summary → evidence drill-down → tested Work adapter where supported → explicit review actions. No date or support guarantee is attached to unverified host capabilities.
