# Agent Progress Studio

**看见活动，检查证据，谨慎判断任务是否完成。**

[English](README.md) · <!-- APS_VERSION -->0.1.1-rc.4<!-- /APS_VERSION --> · [MIT](LICENSE) · **开发预览**

本地浏览器仪表盘，把 Agent 自报计划、实际观察到的活动和明确验收条件分开呈现。运行逻辑使用 Node.js 内置模块和本地页面资源，无需账号、API 密钥、安装 npm 依赖或编译。

**五项边界问题已在独立分支实现修复。** 独立静态复审已完成：五项修复范围内未发现具体源码支持的绕过或正常行为回归。请先用合成数据体验，真实宿主兼容性与人工验收仍未确认。公开源码供开发与审阅，不能称为稳定版或全面安全认证。[问题与限制](docs/KNOWN-ISSUES.md)记录原问题、修复范围和剩余验收条件。

## 用隔离目录开始演示

项目声明支持 **Node.js 22.x（至少 22.17.0）或 24.x（至少 24.2.0）**，范围为 `^22.17.0 || ^24.2.0`。Node 23 与较早的 Node 24 缺少所引用的 Windows 文件元数据修复，已排除；其他主版本尚未声明支持。本轮本机测试环境为 Windows x64、Node 24.17.0；最低版本、Linux 与 macOS 未在本轮获得本机兼容认证，托管结果另行记录。

在源码目录运行：

```powershell
node src/server.mjs --demo --codex-home ./work/synthetic-codex --data-dir ./work/demo-state
```

打开 `http://127.0.0.1:4317`。保持终端运行，Ctrl+C 停止。Windows 也可使用启动器自动打开浏览器：

```powershell
demo.cmd --codex-home ./work/synthetic-codex --data-dir ./work/demo-state
```

显式指定演示数据目录很重要：演示模式仍会为连接列表发现所配置的本地会话目录。上面的目录让演示与正常 Codex 会话及授权记录分开。不要把它们改为真实会话路径，也不要复用已有真实授权数据。

默认端口被占用时加 `--port 4320`。日常启动无需 `npm install`。详见[安装、停止与移除](docs/INSTALL.md)。

## 已实现的能力与限制

| 功能 | 代码提供的行为 | 实际边界 |
| --- | --- | --- |
| 进度 | 分别显示计划步骤比例与加权验收通过率；缺少可靠模型时整体完成度未知。 | 工具次数、Stop 或回合完成不能证明任务完成。 |
| 演示 | 确定性回放、无计划场景、证据弹窗、本机人工决定与 JSON 导出。 | 合成场景不代表真实宿主。 |
| Codex 日志 | 有界文件名发现、逐会话正文授权、日志追加与轮询。 | 属于内部格式的尽力适配，不能确定前台会话或完整历史。 |
| 工程证据 | 单独授权后查看文件、命名测试报告和 Git。 | 读取 Git 证据时关闭签名显示与配置的验证程序；工程授权与会话正文授权仍相互独立。 |
| app-server | 本机回环端点、已加载 ID 发现、单独授权历史及实际收到的通知规范化。 | 不启动、恢复或代答审批；跨客户端订阅未证实；实验分页默认关闭，须通过 API 明确开启；畸形消息被拒绝，不提交半完成状态。 |
| Hook 实验 | 单独安装与信任的可选元数据记录器，以及生命周期、工具名和明确结构化结果。 | 不采集任务正文、计划、Token 或私人工具载荷；读取前核对资源身份，并让每次轮询持有原授权；真实宿主仍待验收。 |
| 页面与人工验收 | 六种验收状态、证据绑定的决定、本机持久化、中英文主题及下载。 | 导出可能含私人路径、源码和任务片段，分享前须自行检查。 |

没有新的非终态活动证据超过 30 秒时，活动变为未知；缺失时间、计划、上下文占用及不支持字段均保持未知。常规轮询间隔为两秒，不承诺固定延迟。

## 验收条件与测试

未来经过复审的真实工程接入，应在所观察工程内定义 `.agent-progress/acceptance.json`。[合成示例](fixtures/acceptance.example.json)关联文件、测试 ID、权重和人工关卡。文件存在只证明已实现；自动验收还需要当前的 `.agent-progress/results.json` 和匹配的源码指纹。人工决定随证据或定义变化而过期。[证据格式](docs/EVIDENCE.md)说明这个约定，它不能证明测试生产者诚实或覆盖完整。

隔离运行 Node 测试及新增边界回归：

```powershell
node scripts/ci-offline.mjs
```

测试包装器创建临时合成用户目录，使用空的开发者 Git 配置，不转交账号密钥、真实会话 ID 或追踪设置；独立修复分支保留原历史，新增 23 项边界回归，并只调整获准修复的 Git、Hook 与 RPC 行为。可选浏览器验证：

```powershell
npm ci --ignore-scripts
node scripts/ci-offline.mjs --browser
```

Windows 浏览器测试使用已安装 Edge；其他平台需要单独准备 Playwright Chromium，本轮未认证这些平台。准备依赖或浏览器可以联网，测试本身使用本地合成数据。生成的报告和截图留在本机且已忽略，CI 不上传它们。

[VERIFICATION.md](docs/VERIFICATION.md)区分本轮实测、历史证据和未验证环境。测试验证合成场景，独立复审针对本轮修复，不能认证所有集成；首轮托管矩阵暴露了 Windows 文件校验差异；后续 PR 修正运行版本要求与合成临时根目录，实际结果见验证记录。

## 隐私和真实宿主

服务绑定本机回环地址，只提供固定资源并检查同源请求。这些是应用控制，不能抵御同一系统用户下的任意程序。[读取范围设计](docs/PRIVACY-SCOPE.md)必须与[修复状态与限制](docs/KNOWN-ISSUES.md)一起阅读。

仪表盘自身无遥测上传或远程页面资源，不修改 Codex/Work 原生界面，不自动安装或信任 Hook。本轮公开准备没有操作真实 Work/Codex 会话；真实宿主版本、通知推送及人工验收仍待验证。
